# Alexandria Audiobook Generator

English | [中文](README_CN.md)

Alexandria is a file-based CLI pipeline for turning books into fully voiced audiobooks. The supported workflow analyzes chapters with Codex CLI, assigns persistent character voices, generates TTS audio, and publishes chapter M4B files.

The legacy Alexandria browser UI and its HTTP API have been removed. There is no local web server in the supported pipeline. Audiobookshelf remains a separate optional service for library management and playback.

## Architecture

- cli.py owns book projects, chapter mapping, analysis state, character IDs, voice IDs, caching, resume, and M4B export.
- app/tts.py is the shared TTS backend. It supports the local Qwen3-TTS engine and external HTTP/Gradio TTS endpoints.
- assets/sfx/ contains the built-in cultivation-novel SFX catalog. Chapter analysis emits controlled cues and FFmpeg mixes them on the dialogue timeline.
- Dasheng-AudioGen can run as a separate external `/sfx` HTTP backend; the local client reaches it through SSH without changing the TTS `/tts` protocol.
- books/<book>/output/chapter_sources/ stores per-chapter source files outside the Audiobookshelf library.
- books/<book>/output/chapters/ contains only fixed-name merged editions watched by Audiobookshelf.
- The audio policy keeps internal mixes at 48 kHz mono PCM 16-bit, then publishes AAC-LC M4B at 44.1 kHz mono 96 kbps with faststart.
- Codex CLI is invoked as an ephemeral read-only subprocess for chapter analysis and summaries.

## Requirements

- Python with the project dependencies installed
- Codex CLI installed and authenticated with codex auth login
- ffmpeg available on PATH
- A local Qwen3-TTS installation or the configured external TTS endpoints
- With the canonical 127.0.0.1:18000/18001 xc endpoints, the CLI automatically checks the remote services over SSH, starts them when needed, creates or reuses the tunnels, and waits for /health; set ALEXANDRIA_XC_TTS_AUTO_START=0 to disable recovery.
- The current `app/config.json` uses the manifest assets regenerated by Dasheng. To generate a cue dynamically later, switch the SFX provider to Dasheng; the CLI will start the xc service and create/reuse the 127.0.0.1:18100 tunnel. Start it manually with `ALEXANDRIA_XC_SFX_BACKGROUND=1 ./start_xc_sfx_tunnel.sh`.
- GPU is recommended for local TTS; external TTS can be used without a local GPU

The default CLI analysis configuration is gpt-5.6-luna with max reasoning. Override it with ALEXANDRIA_CODEX_MODEL or ALEXANDRIA_CODEX_REASONING_EFFORT when needed.

Exact source-text coverage validation is disabled by default, so small omissions, insertions, or rewrites do not block audiobook generation. Set `ALEXANDRIA_COVERAGE_MODE=warn` or `strict` only for explicit diagnostics.

## Quick start

Initialize a book project:

    python cli.py init --book fanren --input /data/books/fanren.epub --title "凡人修仙传"

Plan and generate a range of novel chapters:

    python generate_chapters.py 742 10 --plan
    python generate_chapters.py 742 10 --continue

The range uses the novel original chapter numbers. The count includes the starting chapter.

For parallel analysis with pipelined TTS rendering, use the configurable coordinator; each chapter enters rendering as soon as its analysis is ready:

    .venv/bin/python scripts/generate_parallel.py 774 10 --continue --workers 8

The coordinator also lets the CLI recover the xc TTS services over SSH before rendering.

Inspect status or resume after an interruption:

    python cli.py status --book fanren
    python cli.py run --book fanren --continue

Export a combined M4B when needed:

    python cli.py export --book fanren --format m4b

For a safe preflight without Codex or TTS:

    python cli.py run --book fanren --from 742 --count 1 --dry-run

## Per-book configuration

`app/config.json` remains the global baseline. An optional `books/<book>/config.json` is deep-merged on top of it, so TTS URLs, timeouts, endpoint settings, and other fields not listed by a book continue to inherit the global values.

Create an English book with the matching defaults:

    python cli.py init --book english-book --input /data/books/novel.txt --language English --voice-preset english_narrator

This writes `books/english-book/config.json` and selects English prompts, the `English` TTS language, and the English narrator preset. The same file can be edited manually:

    {
      "language": {"source": "en", "tts": "English", "prompt": "en"},
      "tts": {
        "voice_preset": "english_narrator"
      },
      "sfx": {"enabled": false}
    }

The example intentionally omits TTS URLs, so it still uses the global endpoints. Use `--prompt-locale en` to override only the Codex prompt language, or `--disable-sfx` to disable mixing for one book.

When a book config changes, the next run invalidates only the affected artifacts: language/prompt changes re-run script analysis and summaries, while voice, TTS, or SFX changes re-render audio.

## Sound effects

Sound effects are enabled by default. The catalog contains 21 deterministic, locally generated WAV assets plus 28 user-provided recorded variants for weapon clashes, qi and spell effects, thunder, explosions, movement, creatures, bells, and common ambience. With `auto_generate_missing: true`, existing static assets are used first. If a script contains a cue absent from the manifest, or a manifest asset file is missing, the chapter render automatically calls Dasheng on `xc`, caches the generated WAV under that book's `cache/sfx`, and mixes it into the current chapter. If the service fails, an available static asset is used when possible; otherwise rendering fails with an actionable error. Generation is triggered only for cues already marked in the script; it does not invent effects for ordinary text. The remote deployment is `/mnt/workspace/xinchao.gou/Dasheng-AudioGen` (service port `8100`, local tunnel port `18100`). Dasheng natively returns roughly ten-second clips, so the chapter mixer applies event-level `duration_ms` trimming or looping.

Example SFX configuration:

    "sfx": {
      "provider": "builtin",
      "auto_generate_missing": true,
      "url": "http://127.0.0.1:18100/sfx",
      "cache_dir": "cache/sfx",
      "fallback_to_manifest": true
    }

    python3 scripts/generate_builtin_sfx.py

New chapter analyses write controlled cues into each script line's `effects` array. Re-analyze an existing chapter with `--force` to add automatic cues, then render it normally. `assets/sfx/manifest.json` is the catalog and mixing defaults; with auto-generation enabled, a clearly implied cue can also be generated when it is absent from the catalog. Rendered chapters retain `dialogue.wav` as the speech-only master and write resolved cue timestamps to `sfx_timeline.json`.

Disable mixing for a run with `ALEXANDRIA_SFX_ENABLED=0`. Higher-quality WAV files can replace the built-ins without code changes as long as their manifest cue and filename remain stable.

## Book layout

    books/<book>/
    ├── book.json
    ├── config.json          # optional per-book overrides
    ├── state/
    │   ├── characters.json
    │   ├── aliases.json
    │   ├── voices.json
    │   └── novel_chapters.json
    ├── chapters/000001/
    │   ├── source.txt
    │   ├── script.json
    │   ├── summary.txt
    │   ├── status.json
    │   ├── dialogue.wav
    │   ├── sfx_timeline.json
    │   └── audio.m4b
    └── output/
        ├── chapter_sources/
        └── chapters/        # merged editions only

Analysis and TTS state are checkpointed per chapter. If TTS fails, the next run can reuse the existing analysis and continue from the audio stage.

## Audiobookshelf

Audiobookshelf is not part of the CLI process. The included Compose file only manages the Audiobookshelf service:

    docker compose up -d audiobookshelf

It listens on http://localhost:13378, stores its configuration under data/audiobookshelf/, and reads the project books through the read-only mount ./books:/audiobooks:ro. Enable the Audiobookshelf File Watcher for automatic discovery of newly published chapters.

Publish and verify the rolling `fanren` edition with one command:

    .venv/bin/python scripts/update_serial.py

The command discovers the latest contiguous chapter from chapter 757, exports and atomically publishes the fixed-name M4B, and verifies the result through the Audiobookshelf API. Per-chapter sources remain available, while `output/chapters/fanren_serial.m4b` is the only retained merged edition; temporary range exports are deleted after publication. If the catalog is stale, the command stops the container, backs up SQLite, synchronizes chapters, duration, and file metadata for only the matching book record, restarts the service, and performs a delayed verification. When the Audiobookshelf item points at a different path inside the `/audiobooks` mount, the command also atomically mirrors the generated edition to that indexed path before refreshing metadata. Use `--dry-run` to inspect the range, `--force` to re-encode, or `--skip-audiobookshelf` for a local-only publish.
